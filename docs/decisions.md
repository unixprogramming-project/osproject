# 설계 결정과 근거

아래 수치는 설정을 고르기 위한 **예비 측정**이다 (WSL2, 조건별 3~5회, 측정 중 다른 프로그램 실행 상태). 보고서에는 본측정 값을 쓴다.

## 1. 공통 인터페이스로 전송 모듈 분리
벤치마크와 응용이 같은 전송 코드를 쓰도록 `ipc.h`로 분리한다. 컴파일 시 링크로 고르므로 함수 포인터 호출 비용이 측정에 끼지 않는다.

## 2. POSIX IPC 사용
강의계획서 7주차가 POSIX Advanced IPC이고, 안내문의 이름 규칙이 `/osproject_조번호_용도`를 제시한다. System V는 쓰지 않는다.

## 3. 모든 IPC에 클라이언트별 전용 채널
message queue는 요청 큐 1개로 N:1을 처리할 수 있지만, 조각 메시지가 섞이고 pipe와 구조가 달라져 비교가 어려워진다. 1단계는 같은 구조로 비교한다. 2단계에서 공유 요청 큐는 별도 실험 후보다.

## 4. message queue는 조각 전송, 커널 설정 변경 없음
기본 `msgsize_max`가 8192이고 16KiB부터 `mq_open`이 실패했다. 채점 환경에서 동작해야 하므로 커널 설정에 기대지 않는다.

## 5. message queue 깊이 5
`ulimit -q`가 819200바이트라 클라이언트 8개(큐 16개)에서 깊이 6까지 성공하고 8부터 실패했다. 클라이언트 수별 비교가 깊이 차이로 흔들리지 않도록 모든 조건에서 5로 고정한다.

| 깊이 (클라이언트 1) | 64B 처리량 | 1MiB 처리량 |
|---|---|---|
| 1 | 3.4 MB/s | 378.4 MB/s |
| 5 | 11.2 MB/s | 3382.2 MB/s |
| 10 | 52.1 MB/s | 3881.0 MB/s |

깊이가 작은 메시지 처리량에 큰 영향을 주므로 결과 해석 때 반드시 언급한다.

## 6. shared memory 슬롯 64 × 8KiB
처음에는 8 × 64KiB였다. 작은 메시지도 슬롯 하나를 차지해 8개만 쌓여도 대기가 생겼다. 총용량을 약 512KiB로 고정하고 구성만 바꿔 측정했다 (처리량, 클라이언트 1, 5회 중앙값).

| 슬롯 | 64B | 1KiB | 16KiB | 1MiB |
|---|---|---|---|---|
| 8 × 64KiB | 14.7 | 351.9 | 11297.5 | 12064.5 |
| **64 × 8KiB** | 194.6 | 2609.3 | 15070.4 | 13588.0 |
| 512 × 1KiB | 204.7 | 3064.9 | 5273.4 | 4107.6 |
| 2048 × 256B | 239.3 | 1168.7 | 1445.6 | 1373.0 |

단위 MB/s. 64 × 8KiB가 작은 메시지와 큰 메시지 모두에서 고르게 좋아 기본값으로 정했다.

## 7. 코어 유휴 진입을 별도 실험으로 측정
예비 측정에서 클라이언트 1개 지연이 8개보다 크고, 64B에서 세 IPC가 거의 같았다. 코어가 쉬었다가 깨어나는 시간이 IPC 차이를 가리는 것으로 추정하고 요인만 바꿔 확인했다 (왕복 지연 p50, 5회 중앙값).

| 조건 | pipe 64B | mq 64B | shm 64B |
|---|---|---|---|
| 기본 | 54.6us | 48.1us | 54.8us |
| 모든 코어를 낮은 우선순위 부하로 깨워 둠 | 7.3us | 11.9us | 5.4us |
| 서버와 클라이언트를 한 코어에 고정 | 4.9us | 4.1us | 4.0us |

(`shm` 값은 슬롯 변경 전 구성에서 측정했다. 본측정에서 다시 확인한다.)

본측정은 안내문 조건대로 기본 환경으로 하고, 클라이언트 1개 조건에서 두 변형을 추가로 잰다 (`scripts/exp_idle.sh`). 응용은 스레드가 CPU를 쓰는 동안 통신하므로 예측에는 두 결과를 함께 참고한다.

## 8. 실행 순서를 섞고 매번 프로세스를 새로 실행
시간에 따른 온도, 백그라운드 변화가 특정 조건에 몰리지 않도록 고정 시드로 순서를 섞는다. 조건 사이의 상태가 이어지지 않도록 실행마다 서버와 클라이언트를 새로 띄운다.

## 9. 1단계 벤치마크의 스레드 구성
스레드 3개 조건은 2단계 응용에 적용한다. 안내문 5장은 "1단계와 2단계 모두"라고 밝혔지만 6장 제한 요건에는 그 표현이 없고, 서식도 스레드 설계를 응용 쪽 장에 둔다. 벤치마크 클라이언트는 측정에 다른 스레드가 끼지 않도록 프로세스당 1스레드다. 이 해석을 보고서 2.2에 적는다.

## 10. POSIX API 사용
`epoll`, `eventfd`, `splice`, `F_SETPIPE_SZ`, `getopt_long`을 쓰지 않는다. 예외는 안내문이 지정한 `/proc/self/status`와, 프로그램 밖의 실험 도구(`taskset`, `strace`)다.
