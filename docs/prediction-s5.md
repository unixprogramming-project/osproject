# 보충 측정 S5 예측 (측정 전 작성)

작성: 2026-11-11, `SUPP=S5 scripts/exp_supp.sh` 본측정 전.
동작 확인으로 조건마다 짧은 검증 실행(`--verify`)을 한 번씩 했지만, 종료 코드와 응답 검증 결과만 보고 성능 수치는 보지 않았다.

## 목적

보고서 6.4에서 P5(sys 시간 배수)와 P6(pipe 컨텍스트 스위치)가 예측과 달랐던 이유를 "예측이 1MB 수치를 그대로 쓰고 응답 크기 분포를 반영하지 않았다"고 계산으로만 설명했다.
응답 크기만 바꿔 이 설명을 실험으로 확인한다.

- 바꾸는 요인: 응답 크기 구간만 (`APP_SIZE_CLASS`). 분포대로(mix: 16KB 50%, 256KB 35%, 1MB 15%) / 16KB만 / 256KB만 / 1MB만.
- 고정: 클라 8, 적중 80%, 워커 4, v1(송신 direct), pipe·shm 둘 다. 요청열의 나머지(적중 여부, 필터 등)는 같은 시드로 같다.
- 조건 8개 × 30회 = 240회, 같은 시간대에 섞어서 잰다 (시드 20261114).

## 예측

### P6 확인: pipe 서버의 요청당 자발적 CS는 응답 크기에 비례해 늘어난다
- 계산 근거: 요청을 기다리며 약 1회 + 응답을 64KB(pipe 용량)마다 약 1회.
- pipe: 16KB 1~2.5회, 256KB 4~7회, 1MB 14~20회. mix는 11/8 본측정(4.94회)과 비슷한 4~6회.
- shm(링 512KB): 16KB·256KB 0.8~1.5회, 1MB 1~3회 (링보다 큰 1MB에서만 조금 는다).
- 판정 기준: pipe 1MB 값이 256KB 값의 2.5~4배이고, pipe 1MB가 10회 이상이면 "응답 크기 분포 때문"이라는 설명이 맞다.

### P5 확인: shm 서버 sys는 요청당 거의 일정하고, 그래서 MB당 sys는 작은 응답에서 크다
- shm 요청당 sys 시간은 크기와 거의 무관하다 (1MB가 16KB의 3배 이내).
  따라서 shm MB당 sys는 16KB가 1MB의 10배 이상이다.
- pipe MB당 sys는 크기에 따른 변화가 shm보다 작다 (pipe는 복사하는 바이트에 비례하는 sys가 크다).
- 결과적으로 pipe/shm MB당 sys 배수는 1MB만 보낼 때 10배 이상(원래 예측 P5 수준), 16KB만 보낼 때 5배 미만이다.
- 틀릴 수 있는 점: 1MB 미스마다 1MB 버퍼를 새로 할당하므로 페이지 폴트가 sys에 들어가, 1MB에서 shm sys가 예상보다 클 수 있다.

### P6 확인
| 예측 | 실측 | 판정 |
|---|---|---|
| pipe 16KB 1~2.5, 256KB 4~7, 1MB 14~20, mix 4~6회 | 0.78, 5.27, 17.47, 4.94 | 16KB만 범위보다 적고 나머지 일치 |
| shm 16KB·256KB 0.8~1.5, 1MB 1~3회 | 0.64, 0.93, 1.72 | 16KB만 범위보다 조금 적고 나머지 일치 |
| pipe 1MB가 256KB의 2.5~4배, 1MB 10회 이상 | 3.31배, 17.47회 | 일치 |

pipe CS는 응답 크기에 비례해 늘었다 (1MB 17.5회 ≈ 1MB/64KB 16회 + 약 1회). "응답 크기 분포 때문"이라는 설명이 맞다.
16KB에서 1회 미만인 것은 부하가 계속 있어 워커가 요청을 기다리며 잠들지 않는 경우가 많기 때문으로 본다 (예측의 "요청 대기 약 1회" 가정이 과했다).

### P5 확인
| 예측 | 실측 | 판정 |
|---|---|---|
| shm 요청당 sys는 1MB가 16KB의 3배 이내 | 17.4 / 5.1 = 3.4배 | 불일치 (조금 넘음) |
| shm MB당 sys는 16KB가 1MB의 10배 이상 | 313.0 / 16.6 = 18.9배 | 일치 |
| pipe MB당 sys 변화가 shm보다 작음 | pipe 2.0배 (570/286), shm 18.9배 | 일치 |
| pipe/shm 배수: 1MB 10배 이상, 16KB 5배 미만 | 17.25배, 1.82배 | 일치 |

1MB만 보내면 원래 예측 P5(10배 이상)가 성립하고, 크기가 섞이면 9배, 16KB만이면 1.8배다. 배수가 작아진 이유가 응답 크기 분포라는 설명이 맞다.
다만 shm 요청당 sys는 완전히 일정하지 않고 응답 크기에 따라 늘었다 (5.1 → 17.4us). 1MB에서 CS가 1.72회로 늘어난 것과 미스 버퍼 할당의 페이지 폴트가 후보지만 따로 재지 않았다.

### 재현성, 이상값과 측정 환경
- mix 조건은 11/8 본측정(v1, 클라 8, 적중 80%)과 같은 수준이다: pipe CS 4.94 (11/8 4.94), sys 306 (297) us/MB, shm sys 34.1 (34) us/MB.
- 회차 이상치(MAD x3) 15/240개. 이상치를 빼도 중앙값 변화는 최대 0.72% (pipe 16KB).
- 15개 중 9개가 01:01:24~01:02:39에 모였고, 같은 시각 Windows 시스템 로그에 스토어 앱 자동 업데이트(다운로드·설치) 기록이 있었다. 절전·전원 이벤트는 없었다. 조건을 섞어서 쟀으므로 여러 조건에 고르게 걸렸고 결론은 같다.
